## v1.2.2 (2026-06-10) — 服务器内部错误紧急修复

### 根因

`database.py` 中 `execute_query()` / `execute_insert()` / `init_db()` 的 SQLite 路径错误地将 `sqlite3.Connection` 对象（而非 Cursor）赋值给 `cursor` 变量，导致 `.fetchall()` / `.lastrowid` 调用失败。该问题影响所有依赖数据库查询的 API 端点，表现为前端统一返回 `500 Internal Server Error`。

### 后端修复 (5 文件)

| 文件 | 问题 | 修复 |
|---|---|---|
| `backend/core/database.py` | ① SQLite 路径 `cursor = conn` 导致 `fetchall()` 失败 ② 旧数据库缺少 `patient_gender`/`patient_dob`/`deadline` 列 | ① 统一改为 `cursor = conn.cursor()` ② `init_db()` 新增 ALTER TABLE 迁移块，幂等添加缺失列 |
| `backend/services/audit_service.py` | `write_audit_log()` INSERT 使用 ISO 格式 `YYYY-MM-DDTHH:MM:SSZ`，MySQL DATETIME 列拒绝 | 改为 MySQL 兼容格式 `YYYY-MM-DD HH:MM:SS` |
| `backend/services/knowledge_service.py` | `process_uploaded_file()` INSERT 同上日期格式问题 | 同上 |
| `backend/api/ae.py` | `process_ae()` 直接访问 `req.patient_id`/`req.visit_date`/`req.drug_name` 等属性，但端点未对缺失字段设默认值，导致 `AttributeError` | `/process` 和 `/batch` 端点补齐 9 个字段默认值 |
| `backend/agents/compliance.py` | `get_compliance_report()` 未返回分项得分，前端无法独立展示及时性/完整性评分 | 响应新增 `timeliness_score` 和 `completeness_score` |

### 前端修复 (3 文件)

| 文件 | 问题 | 修复 |
|---|---|---|
| `frontend/src/views/SaeReports.vue` | ① 状态列引用 `row.status`（后端返回 `report_status`）② 详情弹窗引用不存在的 `reporter_name`/`reporter_org` | ① 改为 `row.report_status` ② 替换为 `patient_gender`/`patient_dob`（CIOMS-I 新增字段） |
| `frontend/src/views/Audit.vue` | 列绑定字段名与后端 API 不一致 | `username`→`user_id`, `agent`→`agent_type`, `resource`→`resource_id`, `timestamp`→`created_at` |
| `frontend/src/views/Compliance.vue` | ① 进度环绑定 `data.sae_timeliness`（数组）做数值运算 ② `remaining_days`→`days_remaining` ③ issues 作为字符串数组但模板期望对象 | ① 综合/及时性/完整性三个进度环分别绑定正确数值字段 ② 列名修正 ③ 将 issues 字符串映射为 `{description, severity, source}` 对象 |

## v1.0.0 — 项目初始化

### 核心功能

- **AE 编码**：MedDRA 关键词匹配，严重性/SAE/预期性/因果关系判定
- **SAE 报告**：CIOMS-I 格式自动生成，支持 docx/json/pdf 导出
- **方案偏离检测**：7 条默认规则（PD-001 ~ PD-007），AE 编码后自动联动检测
- **安全性信号挖掘**：后台线程 PRR/ROR/Chi2 统计
- **合规质控**：时限监控 + 字段完整性检查
- **知识库管理**：文档上传 + ChromaDB 向量化 + 向量检索
- **审计日志**：全操作自动记录
- **Mock JWT 认证**：HS256，三级角色

### 技术栈

- **后端**：Python 3.9+ / FastAPI / Uvicorn / ChromaDB / PyMySQL (vendored) / PyJWT (vendored)
- **前端**：Vue3 / Pinia / Element Plus / ECharts / Vite / axios
- **数据库**：MySQL (生产) / SQLite (本地开发)
- **容器化**：Docker Compose (应用 + ChromaDB + 可选 Ollama)

### 架构

```
请求 → FastAPI Router (api/) → Agent (agents/) → Database (database.py)
                                ↕
                       Service (services/)
```
