# 《基于Agentic RAG与多智能体协作的药物临床试验不良事件智能监测与方案偏离预警平台》（Adverse Event & Protocol Deviation Sentinel）

## 一、这个项目是做什么的

**通俗一句话定义**：
这是一个**AI药物临床试验安全监测系统**，不靠大模型瞎编，而是通过**Agentic RAG（智能检索增强生成）**精准检索临床试验方案、不良事件术语库、药物警戒法规、历史试验数据，再通过**多个AI智能体分工协作**，替代临床监查员和药物警戒专员完成不良事件智能识别与编码、方案偏离预警、严重不良事件（SAE）自动报告、同类药物安全性汇总分析等工作，打造一个低成本、高效率、合规的临床试验安全智能监测平台。

**区别于普通AI问答平台的核心亮点**

1. **普通RAG**：用户输入不良事件描述，直接检索相似文本，**不会做标准编码映射（MedDRA）、不会判断严重性、不会关联试验方案**；
2. **Agentic RAG**：具备智能规划能力，能**自主分析不良事件描述、匹配MedDRA术语、判断是否为SAE、检索方案偏离标准、对比历史同类药物安全性信号**，输出符合监管要求的标准化报告；
3. **多智能体协作**：拆分不同专业角色，**一个AI负责不良事件编码、一个负责方案偏离识别、一个负责SAE报告生成、一个负责安全性信号挖掘、一个负责合规校验**，比单一大模型更专业、可溯源、满足GCP规范。

## 二、项目背景与痛点

### 2.1 行业现状痛点

- **临床试验不良事件数量庞大**：一个III期试验可能产生数千甚至上万例不良事件（AE），人工录入、编码、审阅耗时巨大，漏报、错报频发；
- **MedDRA编码专业性强**：需要将口语化症状（如“感觉头晕恶心想吐”）映射到标准低位语（LLT），人工编码依赖经验，不同编码员一致性差；
- **方案偏离发现滞后**：大量方案偏离（如访视超窗、漏做检查）埋藏在病历和CRF中，传统监查难以实时发现，影响试验数据完整性；
- **药物警戒合规要求严**：SAE需在规定时限内（如7天/15天）上报药监部门，手工处理易超期，面临整改甚至叫停风险；
- **同类药物安全性信息分散**：申办方需要定期比对试验药物与同类药物已知不良反应，传统文献检索效率低。

### 2.2 项目解决的核心问题

用 **Agentic RAG + 多智能体协作** 解决：**临床试验不良事件处理效率低、编码不一致、方案偏离发现滞后、SAE报告易超期、同类安全性信息整合困难**的行业痛点，提高临床试验质量与合规性，加速新药上市。

## 三、系统整体架构

整体四层架构：**数据层 → Agentic RAG智能层 → 多智能体业务层 → 前端展示层**

### 1、数据层（知识库）

搭建专属临床试验安全知识库，数据全部来自公开渠道和试验内部文档（脱敏）：

- **MedDRA术语库**（中文版，公众可获取）：系统器官分类（SOC）、高位语（HLT）、低位语（LLT）层级结构；
- **临床试验方案**（结构化导入）：入排标准、访视计划、禁止用药、方案偏离判定规则；
- **药物警戒法规库**：ICH E2A/E2B、GCP规范、NMPA《药物临床试验期间安全性数据快速报告标准和程序》、FDA 21 CFR Part 312；
- **同类药物安全性数据集**：公开的药品说明书（不良反应章节）、FDA/EMA/NMPA审评报告、PubMed药物警戒文献、WHO VigiBase 公开数据（如有许可）；
- **历史SAE报告模板**：CIOMS-I表、中国药物警戒系统报告格式。

处理动作：切片、向量化、入库（向量数据库），同时构建MedDRA编码映射规则库。

### 2、核心智能层：Agentic RAG 引擎

整个系统的大脑，负责所有智能推理：

- 用户意图识别（AE录入、SAE上报、方案偏离查询、信号检测请求）；
- 复杂问题拆解：输入“患者用药后第3天出现恶心呕吐，伴有肝酶升高”，拆解为→ 症状提取→MedDRA编码候选→严重性判断（是否住院/危及生命）→方案相关性分析→是否需要SAE报告；
- 动态多轮检索：先查MedDRA，再查方案中的不良事件预期列表，再查同类药物已知肝毒性信号；
- 答案合规校验：确保SAE报告时限、字段完整性符合药监要求，抑制大模型幻觉（不允许编造因果关系判定）。

### 3、业务层：五大药物警戒智能体

模拟药物警戒部门分工，拆分**5个独立智能体**，互不干扰、协同工作：

#### 智能体1：不良事件智能编码与严重性初筛智能体

- 输入：研究者填写的AE原始描述（中文/英文），输出：MedDRA编码（LLT/PT级别）、严重性分级（轻/中/重）、是否满足SAE标准（死亡/危及生命/住院/残疾/先天异常/其他重要医学事件）；
- 支持批量AE自动编码，一致性校验（对比人工编码结果反馈学习）。

#### 智能体2：方案偏离智能识别与预警智能体

- 持续监测临床试验数据（访视日期、检查完成情况、药物发放记录），自动识别方案偏离，例如：访视窗超期、禁止用药使用、关键检查缺失；
- 输出偏离类型（轻度/重大）、影响分析、建议采取的纠正措施；
- 实时推送预警至CRA（临床监查员）工作台。

#### 智能体3：SAE报告自动生成与合规填报智能体

- 当智能体1识别出SAE后，本智能体自动提取病例信息（人口学、试验药物、不良事件开始时间、转归等），填充CIOMS-I表或NMPA快速报告模板；
- 检索同类药物已知SAE信息，辅助判断因果关系（可能/很可能/无关）；
- 生成报告草稿，供药物警戒专员审核一键导出，同时跟踪报告时限倒计时。

#### 智能体4：药物安全性信号挖掘与聚合分析智能体

- 定期检索PubMed、FDA/EMA/NMPA最新审评报告、WHO VigiBase信号，比对试验药物同靶点/同类别的安全性信息；
- 识别试验中出现的聚集性不良事件（如3例肝损伤），触发信号评估流程；
- 生成DSUR（研发期间安全性更新报告）所需的安全性汇总表。

#### 智能体5：合规与质量控制智能体

- 审核所有AE/SAE记录的完整性、一致性（例如：死亡病例是否记录死亡日期和死因）；
- 校验SAE报告时限（7天/15天），自动提醒超期风险；
- 对照GCP法规检查电子数据存档合规性，输出稽查痕迹。

### 4、前端展示层

用户Web端界面（角色化视图）：

- **药物警戒专员**：AE录入与编码工作台、SAE报告生成与提交、信号监测看板；
- **临床监查员**：方案偏离实时预警、偏离处理跟踪、访视进度报表；
- **医学总监/申办方**：安全性信号总览、DSUR资料导出、多中心AE对比分析；
- **系统管理员**：知识库更新、模型参数配置、用户权限管理。

## 四、核心业务流程

**完整闭环流程（以不良事件处理为例）**：

1. **数据接入**：研究者/CRC在EDC系统中录入AE原始描述，或通过API推送至本平台；
2. **意图识别与路由**：Agentic RAG引擎判断为“不良事件处理”，路由至**不良事件编码智能体**；
3. **智能编码与严重性评估**：自动输出MedDRA编码、严重性分级；若判定为SAE，调用**SAE报告生成智能体**；
4. **方案偏离检测**：同时**方案偏离智能体**检查该次访视是否存在偏离（如未按方案做安全性检查）；
5. **报告生成与预警**：SAE报告智能体生成CIOMS-I表草稿，合规智能体验证字段完整性，推送至药物警戒专员；
6. **信号聚合**：后台**信号挖掘智能体**按周/月汇总AE发生频率，与同类药物背景率对比，生成信号报告；
7. **历史存档与可追溯**：所有处理记录存入审计追踪日志，供药监部门检查。

## 五、项目创新点

1. **技术创新：Agentic RAG助力MedDRA智能编码**
   传统编码依赖人工或简单关键词匹配；本项目利用Agentic RAG自主理解症状描述，动态检索术语层级结构，实现高精度自动编码，编码一致性可提升至90%以上。
2. **架构创新：多智能体模拟药物警戒团队**
   将编码、偏离识别、SAE报告、信号挖掘、合规校验拆分，既符合专业分工，又便于独立优化和替换，适应不同临床试验阶段的业务变化。
3. **业务创新：从AE录入到SAE上报的全流程自动化**
   覆盖了临床试验安全性监测的核心痛点，极大缩短SAE报告制作时间（从小时级到分钟级），降低人为遗漏风险。
4. **效果创新：实时方案偏离预警**
   传统监查依赖周期性 onsite visit，本平台实现电子化实时监测，帮助申办方及时发现数据质量问题，减少因方案偏离导致的试验失败风险。
5. **合规强化：内置GCP法规校验与审计追踪**
   所有AI操作均有日志记录，可导出用于监管稽查，满足《药物临床试验质量管理规范》对电子系统的要求。

## 六、技术栈

- **后端框架**：FastAPI / SpringBoot（任选）
- **大模型**：本地开源模型（Qwen-72B、Llama 3-70B、ChatGLM4）或闭源API（GPT-4o，但推荐本地部署以符合数据安全要求）
- **向量数据库**：Chroma / Milvus / Qdrant
- **RAG核心**：LangChain / LlamaIndex，支持多轮检索与工具调用（Agentic能力）
- **MedDRA处理**：使用官方发布的中文版MedDRA .asc文件，构建解析与检索模块
- **前端**：Vue3 / Element Plus，支持角色化仪表盘
- **数据库**：MySQL（存储病例元数据、编码记录、报告草稿）+ PostgreSQL（审计日志）
- **消息队列**：Redis / RabbitMQ（用于实时偏离预警推送）
- **部署**：Docker + Kubernetes（可选），支持私有化部署（药企数据安全要求）

## 七、常见疑问

### 1、MedDRA数据获取是否合法？

**答**：MedDRA由ICH发布，机构（如药企、CRO）需要订阅，但本平台可面向已订阅MedDRA的企业私有化部署，或使用公开的映射资源进行技术验证。在开发阶段，可使用开源医学术语库（如SNOMED CT部分子集）或自建模拟数据。

### 2、药物临床试验数据敏感，如何保证安全？

**答**：本平台设计为本地化部署（on-premise）模式，支持对接企业内部EDC/CTMS系统，不将任何患者数据上传至公有云。大模型可选用本地开源模型（Qwen、Llama），推理完全在内网完成。

### 3、这个项目商业化价值在哪里？

**答**：

- **目标客户**：创新药企、CRO公司、药物警戒服务外包商。
- **收费模式**：按试验项目授权（每个临床试验5-20万元/年）、SaaS订阅（10-50万元/年视功能模块）、私有化部署定制（50-200万元一次）。
- **市场空间**：中国每年约1000个新药临床试验，药物警戒数字化渗透率不足30%，替代人工成本效益明显。

### 4、公开数据量大吗？可以支撑模型训练？

**答**：

- 不良事件描述：可从FDA FAERS公开数据库下载数百万份真实不良事件报告（脱敏）用于模型微调。
- 方案偏离：公开来源较少，但可通过模拟生成（基于Protocol模板和常见偏离类型）进行预训练。
- MedDRA术语：数万标准术语层级。
- 同类药物安全性：药品说明书、FDA/EMA/NMPA审评报告、PubMed文献，每年数千篇更新。
  这些公开数据足以支撑Agentic RAG的检索与验证。

### 5、与现有药物警戒系统（如Argus、ArisGlobal）有什么区别？

**答**：现有系统主要是录入和管理工具，智能化程度低。本平台基于Agentic RAG和多智能体，实现**从自然语言到结构化报告的全自动转换**和**主动安全信号发现**，可集成到现有系统上方作为智能增强层，而非完全替代。

- 一套基于Agentic RAG的临床试验不良事件智能处理引擎
